## Product (one paragraph)

**Bunkai** (分解) is an **open-core, multi-tenant Test Management System** built on Next.js 15 (App Router) + Supabase (Postgres + Auth + Realtime + Storage) + Vercel. Tagline (working): *"The art of breaking down a kata into its applications."* Distribution targets: **Bunkai Cloud** (hosted SaaS), **Bunkai Community** (self-hosted via Docker Compose — Phase 2 retrofit), **Bunkai Enterprise** (SSO/SAML/audit, license-gated features on the same code).

## Problem (what hurts that we solve)

Existing TMSs (Xray, Zephyr Scale, TestRail, qTest) are *"document vaults with execution glued on top"*. Their data model treats each test case as a monolithic blob of free-form steps in a folder. Consequences:

1. **Step duplication** — a URL change is a 40-file edit.
2. **Broken traceability** — links between User Story → Acceptance Criterion → Test → Run → Bug are "a free-text field nobody fills".
3. **Lying reports** — "80% passing" tells nothing about what those 80% validate.
4. **Bug delegation** — once a test fails, defect context escapes the QA loop into Jira.
5. **Data sovereignty wall** — regulated industries (fintech/healthtech/legaltech) cannot put specs into third-party SaaS; pay enterprise license or build internal hacks.

Deeper problem: incumbent TMSs are *pedagogically neutral*. They let bad QA happen efficiently.

## Scope — MVP (the 30% that differentiates)

| Capability | DB / Code evidence |
|---|---|
| **ATCs (Acceptance Test Cases / Atomic Test Components)** — reusable, atomic, mandatory-anchored to a US + AC, scoped to a Module | `atcs.user_story_id NOT NULL REFERENCES public.user_stories(id) ON DELETE RESTRICT` + M:N table `atc_acceptance_criteria` (`<target>/supabase/migrations/0004_atcs.sql`) |
| **Tests = ordered chains of ATCs** (not free-form step lists) — edit ATC-001 once, every test using it updates | `atcs.version` incremented in `bunkai_save_atc` RPC (`0007_save_atc.sql`); Test entity not yet migrated (see Discovery Gaps) |
| **Workspace → Project → Module hierarchy** for multi-tenant data + feature partitioning | `workspaces` / `projects` / `modules` (tree, materialized path, depth ≤ 6) — `0001`, `0002` |
| **Tree view + Table view** as equal-citizen views over same data | UI routes `/projects/[projectSlug]` + components in `<target>/components/atcs/` |
| **Manual execution** — step-by-step runner with pass/fail/block, evidence notes, bug reporting in-place | `atcs.status` enum: `pass · fail · blocked · skipped · running · unrun` |
| **Native bug management** anchored to Module + ATC + Run; optional Jira sync (not delegation) | Bug entity referenced in product canon — **not yet in migrations 0001-0008** (Discovery Gap) |
| **REST API + OpenAPI spec + minimal CLI** — external operators (AIs, scripts, CI) can drive Bunkai | `<target>/app/api/openapi/route.ts`, `<target>/public/openapi.json`, `<target>/app/api/v1/*`; `access_tokens.scopes` includes `run:execute` for the agent surface |
| **VS Code aesthetic** — dark mode default, high density, monospace for IDs, command palette (Cmd+K), kanji wordmark | `@monaco-editor/react`, `cmdk`, shadcn / Radix UI primitives (in `bun.lock`) |

Out of MVP scope (Phase 2+): mind-map / graph view, 3D toggle, agentic execution mode (UI layer), Docker Compose self-host distribution retrofit.

## Constraints

- **Tech stack locked**: Next.js 15 App Router + Supabase + Vercel. No alternative substrates planned for MVP.
- **Open-core license**: Apache 2.0 or MIT (TBD before launch). Affects what this QA framework can re-distribute.
- **Multi-tenant boundary**: workspace (every row resolves to a `workspace_id`). RLS enforced.
- **Bunkai Cloud is the priority distribution** for MVP; Community Docker Compose ships Phase 2 (after Cloud PMF signal).

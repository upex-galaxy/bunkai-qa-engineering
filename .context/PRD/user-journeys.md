### QA framework coverage plan

- **Keyboard accessibility**: Cmd+K command palette path → ATC creation without mouse.
- **Performance**: full path completes <10 min on staging with `~2k existing modules` baseline (Mateo's bar).

            │
            ▼
Walk through 7 ATCs in sequence
   ├── ATC-001 step 1 ──► P (pass) keyboard shortcut
   ├── ATC-001 step 2 ──► P
   ├── ...
   └── ATC-005 step 3 ──► F (fail) — discount field rejects valid code
            │
            ▼
Bug form pre-fills (Module, ATC, steps-to-reproduce, env)

   └── Optional Jira sync (if configured)
            │
            ▼

            │
            ▼

## Journey 3 — AI agent runs a Test via API (Karim, nightly regression)

**Goal**: Headless agent runs TEST-008 against staging at 02:00 UTC and reports outcomes; files Bugs on failure.

**Trigger**: Scheduled job. Agent has a Bearer PAT with scopes `atc:read` + `run:execute` (+ `atc:write` if it also files bugs).

```
[Cron 02:00 UTC]
       │
       ▼
GET /api/v1/me                             (Bearer ──► 200 + scopes confirmed)
       │
       ▼
GET /api/v1/tests/TEST-008?expand=atcs.steps,atcs.assertions
       │      (full payload: ATCs ordered, steps + assertions, layer hints, env hints)
       ▼
POST /api/v1/runs
   body: { test_id, environment, executor: {type: "agent", identity}, idempotency_key }
       │
       ▼
   201 RUN-451   (idempotency key recognized on retry — same RUN id returned)
       │
       ▼
For each step:
   ├── Drive app via Playwright
   └── POST /api/v1/runs/RUN-451/steps/[stepId]/result
        body: { status: "pass"|"fail", duration_ms, evidence_url }
       │
       ▼
On step fail:
   ├── POST /api/v1/runs/RUN-451/steps/[stepId]/result  (status: "fail")
   └── POST /api/v1/bugs
        body: { title, module_id, severity, atc_id, run_id, steps_to_reproduce, description }
       │
       ▼
POST /api/v1/runs/RUN-451/finish
   body: { status: "failed", finished_at }
       │
       ▼
[Supabase Realtime broadcasts run finalization to subscribers]
```

## Cross-journey invariants (QA framework's regression bedrock)

These are properties that MUST hold across all journeys — break any of them and Bunkai's value prop collapses. The framework should own a P0 smoke for each.

| # | Invariant | DB / code basis | Test type |
|---|---|---|---|
| 1 | Every ATC is anchored to a User Story | `atcs.user_story_id NOT NULL` | API + DB assertion |
| 2 | Every ATC is anchored to ≥1 Acceptance Criterion | M:N `atc_acceptance_criteria` (app-enforced) | API assertion at create time |
| 3 | Workspace `slug` is globally unique | `workspaces.slug` UNIQUE | API error on duplicate |
| 4 | Module tree depth ≤ 6 | CHECK constraint in `0002` | API error on overflow |
| 5 | RLS isolation across workspaces — no user sees another workspace's data | RLS policies on every table | API auth + cross-tenant attempt → 403/404 |
| 6 | PAT scopes are non-empty and restricted to the 4 allowed values | CHECK constraints in `0008` | API error on invalid scope set |
| 7 | OpenAPI spec at `/api/openapi` matches checked-in TypeScript types | `bun run api:sync` diff | CI gate |
| 8 | Magic-link auth flow completes round-trip (request → callback → session) | `middleware.ts` + `<target>/app/auth/callback/route.ts` | E2E smoke |

## 4. Authentication flow (captured from code)

> **No live login executed against staging.** Test users not yet provisioned in Supabase Auth (Discovery Gap). The following is the authoritative flow from code; once a test user exists, run an E2E probe to confirm the request/response shapes match this spec.

### 4.1 Magic-link request

**Endpoint**: `POST /api/v1/auth/magic-link`

**Implementation**: `<target>/app/api/v1/auth/magic-link/route.ts`.

**Request body** (Zod schema):
```ts
const BodySchema = z.object({
  email: z.string().email(),
  next: z
    .string()
    .min(1)
    .refine(value => value.startsWith('/') && !value.startsWith('//'), {
      message: 'next must be a root-relative path (e.g. /projects).',
    })
    .optional(),
});
```

**Flow** (server-side):
1. Validate body.
2. Build redirect URL: `${webUrl('/auth/callback')}?next=${encodeURIComponent(next ?? '/projects')}`.
3. Create Supabase server client (`createClient` from `<target>/lib/supabase/server.ts`).
4. Call `supabase.auth.signInWithOtp({ email, options: { emailRedirectTo: redirect } })`.
5. On error: map `429` → `rate_limited`; any other → `upstream_error` (status from upstream, default 502).
6. Success: `{ ok: true }` with 200.

### 4.2 Magic-link callback

**Endpoint**: `GET /auth/callback?code=<code>&next=<path>`

**Implementation**: `<target>/app/auth/callback/route.ts`.

**Flow**:
1. Parse `code` + `next` from query string.
2. Validate `next` is root-relative (open-redirect guard) — fallback to `/projects`.
3. If no `code` → `302 /login?error=missing_code`.
4. `supabase.auth.exchangeCodeForSession(code)`.
5. On error → `302 /login?error=otp_exchange_failed&reason=<encoded msg>`.
6. Success → `302 ${origin}${safeNext}` with rotated cookies set by Supabase SSR adapter.

### 4.3 Middleware session check

**File**: `<target>/middleware.ts`. Matcher: `'/((?!_next/static|_next/image|favicon.ico|.*\\..*).*)'`.

**Constants**:
- `PROTECTED_PREFIXES = ['/projects', '/onboarding']`
- `PUBLIC_PREFIXES = ['/login', '/auth', '/api/auth']`

**Flow**:
1. Create `@supabase/ssr` server client with cookie adapter (read + write both implemented inline; this is the canonical place to write rotated cookies).
2. Call `supabase.auth.getUser()` (refreshes session if expired).
3. If `!isPublic(pathname) && isProtected(pathname) && !user` → `302 /login?next=<pathname>${search}`.
4. Else → `NextResponse.next({ request })` with rotated cookies on the response.

### 4.4 Onboarding redirect logic

**File**: `<target>/app/(app)/onboarding/page.tsx` (server component).

**Flow**:
1. `supabase.auth.getUser()` → if missing, `redirect('/login?next=/onboarding')`.
2. Query `workspace_members` for `(user_id = uid, status = 'active') limit 1`.
3. If membership exists → `redirect('/projects')`.
4. Else → render `<OnboardingForm userEmail={user.email}>` (client component handling slug input + RPC call).

### 4.5 Workspace bootstrap RPC

**RPC**: `public.bunkai_bootstrap_workspace(p_slug, p_name)` — `<target>/supabase/migrations/0006_bootstrap_workspace.sql`. SECURITY DEFINER.

**Caller flow** (presumed — Route Handler not yet checked-in):
1. Client calls RPC via `<target>/lib/supabase/rpc.ts > bootstrapWorkspace(supabase, { slug, name })`.
2. RPC validates `auth.uid()` is non-null; raises `42501` otherwise.
3. Validates slug regex `^[a-z0-9][a-z0-9-]{1,38}[a-z0-9]$`; raises `22023` on mismatch.
4. Validates `length(trim(p_name)) >= 1`; raises `22023` on empty.
5. INSERTs `workspaces` + `workspace_members` atomically (owner membership).
6. Returns new `workspace_id` (uuid).

## 5. PAT (Personal Access Token) issuance flow

**Endpoint**: `POST /api/v1/tokens` — `<target>/app/api/v1/tokens/route.ts`.

**Token shape**: `bk_pat_<12-char-prefix>.<remaining-secret>`.

**Server-side flow**:
1. `supabase.auth.getUser()` — must have active session; else `unauthorized` (401).
2. Validate body (Zod): `{ name?: string≤80, scopes: ALLOWED_SCOPES[] (non-empty), workspace_id?: uuid, expires_in_days?: int 1-365 }`.
3. Generate secret: 32 bytes via `crypto.getRandomValues` → base64url.
4. `token_prefix = secret[0..12]`.
5. `hash = SHA-256(secret) hex`.
6. `expires_at = expires_in_days ? now + N*86400000ms : null`.
7. Insert via service-role client (`<target>/lib/supabase/admin.ts`) into `access_tokens` table with `{ user_id, workspace_id, name, token_prefix, hash, scopes, expires_at }`.
8. Return 201 `{ id, token: "bk_pat_<prefix>.<remainder>", name, scopes, workspace_id, expires_at, created_at, warning: "Store this token now — it cannot be retrieved later." }`.

**Bearer middleware (not yet implemented — Phase F)**: comment in `<target>/app/api/v1/tokens/route.ts` describes the intended verification:
- Lookup row by `token_prefix` (O(1) — index `access_tokens_token_prefix_idx`).
- Constant-time SHA-256 hash comparison.
- Reject if `revoked_at IS NOT NULL` OR `expires_at < now`.
- Enforce required scope on the calling route.

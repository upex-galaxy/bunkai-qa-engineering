> Generated by `/project-discovery` Phase 2 (Architecture / SRS) on 2026-05-23. FR = Functional Requirement (capability the system MUST provide). BR = Business Rule (constraint the system MUST enforce). Anchored to verbatim source in `<target>/app/api/v1/*` + `<target>/supabase/migrations/*` + `<target>/lib/api/*`. Future-tense items (Bug/Test/Run) marked `(planned)`.

## 1. Authentication & Sessions

### FR-001 — Magic-link sign-in

**Description**: Users sign in via email magic-link (Supabase OTP). System sends a one-time link; clicking it exchanges a `code` for a session.

**Preconditions**: User has access to the email they supply. Email format is valid.

**Implementation**: `POST /api/v1/auth/magic-link` (`<target>/app/api/v1/auth/magic-link/route.ts`) → `signInWithOtp({ email, options: { emailRedirectTo } })`.

**Postconditions**: Email sent (delegated to Supabase Auth / Resend). User receives link of form `<host>/auth/callback?code=<code>&next=<path>`. On click, `GET /auth/callback` exchanges the code → session cookies → 302 to `next` (or `/projects` default).

**Errors**:
- `validation_failed` (422) if email missing / malformed.
- `validation_failed` (422) if `next` is not root-relative.
- `rate_limited` (429) when Supabase Auth rate-limit fires (mapped from upstream 429).
- `upstream_error` (502) for any other Supabase Auth error.

### FR-002 — Magic-link callback exchange

**Description**: Receive the OTP code from the email link and trade it for a Supabase session.

**Implementation**: `GET /auth/callback?code=<code>&next=<path>` (`<target>/app/auth/callback/route.ts`).

**Errors**:
- 302 → `/login?error=missing_code` if `code` query missing.
- 302 → `/login?error=otp_exchange_failed&reason=<msg>` on Supabase exchange failure.

### FR-003 — Session check on protected routes

**Description**: Edge middleware checks Supabase session on every navigation. Unauthenticated requests to protected paths redirect to login.

**Implementation**: `<target>/middleware.ts`. Matcher `'/((?!_next/static|_next/image|favicon.ico|.*\\..*).*)'`. Protected prefixes `['/projects', '/onboarding']`. Public prefixes `['/login', '/auth', '/api/auth']`.

**Postconditions**: Authenticated user → `NextResponse.next()` with refreshed cookies. Unauthenticated user on protected path → 302 to `/login?next=<pathname+search>`.

### FR-004 — Sign out

**Description**: Authenticated user can sign out, clearing the Supabase session.

**Implementation**: `AuthProvider.signOut()` in `<target>/components/providers/auth-context.tsx` → `supabase.auth.signOut()`.

## 2. Personal Access Tokens (PATs)

### FR-010 — Issue PAT

**Description**: A signed-in user issues a Personal Access Token to authenticate CLIs or AI agents.

**Preconditions**: Active session (`supabase.auth.getUser()` returns a user).

**Inputs** (Zod-validated): `{ name?, scopes: string[] (non-empty), workspace_id?: uuid, expires_in_days?: int 1-365 }`.

**Implementation**: `POST /api/v1/tokens` (`<target>/app/api/v1/tokens/route.ts`).
- Generates 32-byte random secret (base64url).
- `token_prefix` = first 12 chars; `hash` = SHA-256 hex.
- Inserts via service-role client into `access_tokens`.
- Returns plaintext token exactly once: `bk_pat_<prefix>.<secret>`.

**Postconditions**: `access_tokens` row created. Plain secret never persisted.

**Errors**:
- `unauthorized` (401) if no session.
- `validation_failed` (422) if scopes empty / contain unknown scope / `expires_in_days` out of range / `workspace_id` not UUID / `name` over 80 chars.
- `internal_error` (500) on DB insert failure.

### FR-011 — List own PATs

**Description**: Signed-in user lists their own (non-revoked + revoked) tokens. Hash is never returned.

**Implementation**: `GET /api/v1/tokens` (`<target>/app/api/v1/tokens/route.ts`).

**Returns**: `{ tokens: [{ id, name, scopes, workspace_id, token_prefix, expires_at, revoked_at, last_used_at, created_at }] }` ordered by `created_at DESC`.

**Errors**: `unauthorized` (401) if no session.

### FR-012 — Soft-revoke PAT

**Description**: Signed-in user revokes one of their PATs by setting `revoked_at = now()`. Row not deleted (audit retained).

**Implementation**: `DELETE /api/v1/tokens/[id]` (`<target>/app/api/v1/tokens/[id]/route.ts`).

**Postconditions**: 204 on success. Row's `revoked_at` populated. Bearer middleware (Phase F) will reject the token afterwards.

**Errors**:
- `unauthorized` (401) if no session.
- `validation_failed` (422) if `[id]` not UUID.
- `not_found` (404) if token missing OR already revoked OR not owned by caller (RLS denies match).

### FR-013 — PAT bearer authentication (planned)

**Description** (planned): API requests carrying `Authorization: Bearer bk_pat_<prefix>.<secret>` are authenticated server-side: lookup by `token_prefix` (O(1)), constant-time SHA-256 hash compare, check `expires_at` and `revoked_at`, enforce scope on the route.

**Status**: Not implemented. All `/api/v1/*` today are session-cookie-only. Marked `Phase F` in code comments. Discovery Gap.

## 3. Workspace lifecycle

### FR-020 — Bootstrap workspace (atomic)

**Description**: Creating a workspace must atomically also create the owner's `workspace_members` row. Solving the chicken-and-egg of RLS that requires admin role to insert into `workspace_members`.

**Implementation**: RPC `public.bunkai_bootstrap_workspace(p_slug, p_name)` (`<target>/supabase/migrations/0006_bootstrap_workspace.sql`). SECURITY DEFINER. Caller must be authenticated.

**Postconditions**: One `workspaces` row + one `workspace_members` row (owner) created atomically.

**Errors**:
- `not_authenticated` (SQLSTATE `42501`) if `auth.uid()` is NULL.
- `invalid_slug` (`22023`) if slug doesn't match `^[a-z0-9][a-z0-9-]{1,38}[a-z0-9]$`.
- `invalid_name` (`22023`) if name is null or only whitespace.

### FR-021 — Workspace CRUD via RLS (planned routes)

**Description**: `GET/PATCH/DELETE /api/v1/workspaces/[id]` routes not yet checked-in. RLS already enforces:
- SELECT: any `workspace_members` with `status='active'`.
- INSERT: only via RPC above (the policy `workspaces_insert_self_owner` requires `auth.uid() = owner_user_id`, which is what the RPC sets).
- UPDATE / DELETE: only `owner` role + `status='active'`.

## 4. Membership & RBAC

### FR-030 — List workspace members

**Description** (planned route): A user lists members of a workspace they belong to.

**RLS policy** (`workspace_members_select_self_or_admin` in `0005_rls_helpers.sql`): user sees own row always; user with `admin`/`owner` role sees all rows in the workspace.

### FR-031 — Invite member

**Description** (planned route): Admin / owner adds a member with `status='invited'`. Status transitions to `active` upon user acceptance (Discovery Gap — invitation flow UI not yet visible in code).

**RLS policy** (`workspace_members_insert_admin`): caller must be `admin` or `owner` with `status='active'`.

### FR-032 — Change member role

**Description** (planned route): Admin / owner promotes / demotes a member.

**RLS policy** (`workspace_members_update_admin`): same constraint as invite.

### FR-033 — Suspend / remove member

**Description** (planned route): Admin / owner suspends (status → `suspended`) or removes (DELETE row).

**RLS policy** (`workspace_members_delete_admin`).

## 6. ATC (Acceptance Test Case) authoring

### FR-050 — ATC CRUD (planned routes)

**RLS policies** (`atcs_*_workspace_role_member_plus`): join `projects → workspaces`. Composite uniqueness `(project_id, slug)`.

**Required fields** at INSERT (from `0004_atcs.sql`):
- `project_id` (NOT NULL, FK)
- `module_id` (NOT NULL, FK)
- `user_story_id` (NOT NULL, FK with `ON DELETE RESTRICT` — **anchoring moat**)
- `slug` (NOT NULL)
- `title` (NOT NULL)
- `layer` (NOT NULL, CHECK in `('UI','API','Unit')`)

**Defaults**:
- `version = 1`
- `status = 'unrun'`
- `tags = '{}'`

### FR-051 — Bulk-save ATC (steps + assertions + AC links)

**Description**: Save an ATC with all its children atomically. Replace-on-write semantics for steps and assertions.

**Implementation**: RPC `public.bunkai_save_atc(p_atc_id, p_title, p_layer, p_tags, p_user_story_id, p_steps jsonb, p_assertions jsonb, p_ac_ids uuid[])` (`<target>/supabase/migrations/0007_save_atc.sql`). SECURITY INVOKER — RLS evaluated as caller.

**Postconditions**:
- `atcs.version` incremented by 1.
- All existing `atc_steps` for the ATC deleted; re-inserted in order from `p_steps` (positions 0..n-1).
- All existing `atc_assertions` deleted; re-inserted from `p_assertions`.
- All existing `atc_acceptance_criteria` deleted; re-inserted from `p_ac_ids` (if non-null).

**Errors**:
- `atc_not_found` (`22023`) if no row matches `p_atc_id`.

### FR-052 — Full-text search ATCs (planned route)

**Description**: Search ATCs by title + tags via GIN-indexed tsvector. Trigger `atcs_refresh_tsv` keeps `tsv` in sync on title/tags changes.

**Implementation**: `tsv` column + GIN index `atcs_tsv_gin_idx` already in place (`0004_atcs.sql`). Search endpoint not yet routed.

## 7. Cross-cutting API behavior

### FR-060 — Request correlation via `x-request-id`

**Description**: Every API response carries `x-request-id`. If the inbound request supplies one (1-128 chars), reuse it; otherwise mint a UUID.

**Implementation**: `<target>/lib/api/request-id.ts` + `<target>/lib/api/handler.ts`.

### FR-061 — Canonical error envelope

**Description**: Every error from `/api/v1/*` returns `{ error: { code, message, details?, request_id? } }` with HTTP status matching the code.

**Implementation**: `<target>/lib/api/error-envelope.ts`. Stable codes: `bad_request` (400), `validation_failed` (422), `unauthorized` (401), `forbidden` (403), `not_found` (404), `method_not_allowed` (405), `conflict` (409), `idempotency_key_required` (400), `idempotency_key_invalid` (400), `rate_limited` (429), `internal_error` (500), `upstream_error` (502).

### FR-062 — Idempotency header validation

**Description**: Routes that need to be safe under retries (planned: `POST /api/v1/runs`) require `idempotency-key` header matching `[a-zA-Z0-9_-]{8,128}`.

**Implementation**: `<target>/lib/api/idempotency.ts`. **Persistence (replay store) not yet implemented** — header validation only.

### FR-063 — Structured access logging

**Description**: Every request emits one JSON line on stdout with `request_id`, `method`, `path`, `status`, `duration_ms`. Errors include `error_code`.

**Implementation**: `<target>/lib/api/logging.ts`.

### FR-064 — OpenAPI spec served at `/api/openapi`

**Description**: Static OpenAPI 3 spec served from `<target>/public/openapi.json`. Cached 5 min.

**Implementation**: `<target>/app/api/openapi/route.ts` (`export const dynamic = 'force-static'`, `cache-control: public, max-age=300, s-maxage=300`).

### FR-065 — Health check

**Description**: `GET /api/v1/health` → `{ ok: true, service: 'bunkai-tms', env, ts }`.

**Implementation**: `<target>/app/api/v1/health/route.ts` (`force-dynamic`).

## 9. State machines (referenced from `domain-glossary.md`)

### SM-001 — ATC status lifecycle

States: `unrun → running → {pass | fail | blocked | skipped}`. Any non-running state can transition back to `running` on re-run. Enforced application-side (no DB trigger).

### SM-002 — Workspace member status lifecycle

States: `invited → active → {suspended ↔ active}`. Removal = row deletion (CASCADE on workspace or user delete).

### SM-003 — PAT lifecycle

`active (revoked_at IS NULL) → revoked (revoked_at IS NOT NULL)`. Terminal. Future agents need a new PAT.
